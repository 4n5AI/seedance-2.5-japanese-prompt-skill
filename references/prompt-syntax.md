# Seedance 2.5 プロンプト記法ガイド

Seedance 2.5 に固有の書式（音声・字幕の括弧記法、時間指定、参照素材の束縛、ネガティブ指定、モデルが解釈する語彙）をまとめる。カメラの動きは [camera-movements.md](camera-movements.md)、レンズと被写界深度は [lens-and-focus.md](lens-and-focus.md)、ショットサイズ・アングル・構図は [shot-composition.md](shot-composition.md)、光と色は [lighting-color.md](lighting-color.md)、複数ショットの連続性は [multi-shot-continuity.md](multi-shot-continuity.md) を参照する。

**確度の表記**：各項目に確度を付ける。

- **【公式】** Dreamina／ByteDance の公式資料で本文を確認したもの（[source-guide.md](source-guide.md) の指定3資料）。
- **【第三者】** 公式ガイドを解説する第三者記事で、複数の独立した情報源が一致するもの。公式の一次文面は未確認。
- **【未確認】** 情報源が単一、または裏付けが弱いもの。ユーザーへ断定して伝えない。

**【第三者】の項目をユーザーへ説明するときは、「公式資料で未確認」であることを添える。数値や仕様を発明しない。**

---

## 1. バージョンの取り違えに注意（最重要）

**Seedance 2.0 向けの助言を 2.5 に適用しない。** 特に時間指定の方針が逆になっている。

| 項目 | Seedance 2.0 | Seedance 2.5 |
|---|---|---|
| 時間指定 | タイムスタンプを付けず、`Shot 1 / Shot 2` のラベルで順序だけ示す。秒に固定すると出力が悪化するとされる | **秒単位のタイムスタンプに対応**。`0〜3秒:` のような区間指定が推奨される |

Web上には 2.0 向けの記事が多く残っている。「タイムスタンプを付けるな」という助言を見かけても、2.5 では時間区間で書いてよい。ただし §3 の制約は守る。確度は**【第三者】**（2.0／2.5 双方の解説記事が一致してこの差を述べる。公式の一次文面は未確認）。

## 2. 音声・字幕の括弧記法

発話・効果音・音楽・画面上の文字を括弧で書き分ける。**確度【第三者】**（複数の独立した解説記事が同じ割り当てを報告）。

| 内容 | 記号 | 例 |
|---|---|---|
| 音楽・環境音 | `( )` | `(静かなピアノ、低いアンビエント)` |
| 効果音 | `< >` | `<ベルが鳴る>` |
| 発話するセリフ | `{ }` | `{2,000年のえいちをエーアイで未来へ。}` |
| 画面上の字幕・タイトル | `【 】` | `【第1章】` |

運用ルール。

- **括弧は任意。** 平文でも動作するとされる。括弧の目的は、セリフが字幕として画面に描画される／効果音が読み上げられる、といった取り違えを防ぐこと。ユーザーが平文を望む場合は無理に使わない。
- **セリフと字幕は別チャンネル。** 聞かせたい かつ 画面にも出したい場合は、`{ }` と `【 】` の両方に同じ文を書く。片方だけなら片方だけに書く。
- **言語・声質・話し方は `{ }` の外に先出しし、`{ }` の中は発話する語だけにする。**
  - 例：`セリフ言語：日本語。落ち着いた低めの女性の声、ゆっくりと。{2,000年のえいちをエーアイで未来へ。}`
- **リップシンクの3規則（難読漢字→ひらがな／数値→算用数字／英語→カタカナ）は `{ }` の中のテキストに適用する。** `【 】` の字幕は表示用の文字なので、ユーザーが字幕の表記を別に指定した場合はそれに従う。参照タグ・ファイル名・URL は改変しない。

## 3. 時間指定（タイムスタンプ）の規則

**確度【第三者】。** 公式が秒単位のタイムスタンプに対応すると解説記事が一致して述べる。以下の制約も同様に第三者由来。

守る条件。

- **整数秒で書く。** 秒未満・小数を書かない。
- **区間を隙間なく連続させる。** `0〜3秒` の次を `5〜8秒` にするような欠落を作らない。区間の合計を全体尺に一致させる。
- **1区間は3秒以上を目安にする。** 短い窓に細かい出来事を詰めると、モデルが中間の動きを推測して破綻しやすい。
- **1区間＝1主要アクション＋主要カメラ移動1つ**（多くても方向が矛盾しない2つまで）。
- **30秒なら区間は4〜6本まで。** 詰め込みすぎない。1区間あたりは5〜7秒程度になる。
- **区切りの表記は統一する。** `0〜3秒:` でも `0-3s:` でもよいが、1つのプロンプト内で混在させない。
- **秒を回数の指定に使わない。** 「1秒に3回うなずく」のような頻度指定は機能しないとされる。
- タイムスタンプは**各出来事への時間の割り当て**であり、フレーム単位の編集点ではない。秒の精度を効かせたいのは、受け渡し・登場・転換・音の合わせどころなど**重要な瞬間だけ**にする。

尺の配分例（30秒・ワンカット）。**確度【第三者】**、あくまで出発点。

| 区間 | 役割 |
|---|---|
| 0〜6秒 | 状況を提示する（establish） |
| 6〜14秒 | 展開する（develop） |
| 14〜24秒 | 転じる（turn） |
| 24〜30秒 | 収める（settle） |

### 代替：Shot番号で書く

時間を厳密に配分する必要がなく、テンポをモデルに委ねたいときは `Shot 1:` `Shot 2:` のラベル形式でもよい。**確度【第三者】**（どちらの形式でも可と解説される）。

- **時間区間を使う**：音・セリフ・動作を尺に合わせたいとき、納品尺が決まっているとき。
- **Shot番号を使う**：カットの順序だけが重要で、各カットの長さを任せたいとき。

「次に」「続いて」のような接続語で順序を示す書き方は、推奨として記載された資料が見つかっていない。**【未確認】**なので、順序を明示したいときは時間区間か Shot番号を使う。

## 4. ワンカット（連続撮影）の指定

- 英語で **`one-take shot`** と書く。`continuous shot` / `no cuts` を添えてもよい。`one-take shot` はモデルが解釈する語彙として挙げられている。**確度【第三者】**。
- ワンカットを狙うときは、**1つの進化する運動として散文で書く**。始まりと終わりのある弧を描き、無関係な動作を3つ積み重ねない。
- ワンカットでも §3 の時間配分を併記してよい。各区間には「何が変わるか」と「その原因」を書く。

## 5. 参照素材の役割を束縛する

**素材を並べるだけでは、どの素材が何を制御するのかモデルは推測できない。** 役割を文中で明示する。**確度【第三者】**（公式ガイドが必須事項および禁止パターンとして扱うと解説される）。

文型。

```text
@Image1 は〈主体〉の〈外見・構造〉を定義する。
@Video1 は〈動き・カメラ〉を定義する。
@Audio1 は〈声質・テンポ〉を定義する。
```

- **禁止**：役割を宣言せずに参照を列挙する。
- **参照タグを動詞に直結させない。** `@Image1が走る` のように数字と次の語が続くと解釈が曖昧になる。`Image1 の女性が走る` のように名詞を挟む。
- **再登場点でアイデンティティを再宣言する。** カットをまたいで人物が再び映るとき、識別特徴（年齢・髪型・服・体格など）を短く再掲する。人物が多いショットほど、各人物に十分な参照と記述が必要。
- 実際にアップロードされる素材の順序・タグに合わせる。**未提供の素材を存在するものとして書かない。**

参照素材の枚数・尺の上限と安定域は [source-guide.md](source-guide.md) の表を参照する（**【公式】**）。上限まで使うことを推奨しない。

## 6. ネガティブ（除外）指定

**確度【第三者】。** 2.5 ではネガティブ指定が安定して効くとされる。専用のパラメーターではなく、プロンプト本文に平文で書く。

効きが報告されている定型。

| 目的 | 書き方 |
|---|---|
| 字幕を出さない | `no subtitles` / `no captions` |
| BGMを付けない | `no background music`（環境音は残すなら `keep the room sound` を添える） |
| 画面上の文字を出さない | `no text overlays` |
| カットを割らせない | `no jump cuts` |
| 手振れを入れない | `no camera shake` |
| 背景に同じ人物を並べない | `no identical clones in the background` |

- **該当する区間の中と、プロンプト末尾の締めの2か所に書く**と効きやすいとされる。
- **ユーザーが言っていない禁止事項を全件共通で付け足さない。** セリフや音楽の要否はユーザーの指定に従う。除外が必要な理由があるときだけ書く。

## 7. モデルが解釈する語彙

公式ガイドがカメラ用語を英語のまま（翻訳不要と明記して）列挙していると解説される一覧。**確度【第三者】**。

| 区分 | 語彙 |
|---|---|
| ショットサイズ | `extreme wide`, `wide`, `medium`, `close-up`, `extreme close-up` |
| 移動 | `push in`, `pull out`, `pan`, `lateral move`, `follow shot`, `orbit`, `dive`, `dolly out`, `tilt`, `handheld shake` |
| アングル | `low angle`, `overhead`, `first-person` |
| 特殊 | `one-take shot`, `dolly zoom`, `aerial`, `FPV`, `bullet time`, `bounce speed ramp` |

上の一覧にない珍しい用語を使うときの書式。**確度【第三者】**。

```text
用語 ＋ 対象となる被写体 ＋ 視覚的な変化 ＋ 前景／背景の関係 ＋ 方向または速度
```

例：`Bounce speed ramp。走る人物が跳ね上がる瞬間だけ極端なスローになり、背景の街灯が伸びて流れ、着地でふつうの速度へ戻る。`

### プロンプトの言語について

- **プロンプト全体は日本語で書いてよい。** Seedance は日本語を含む複数言語の入力に対応し、日本語のセリフを含む出力も作れる。
- カメラ用語を英語で書き、対象と意図を日本語で補う「英語用語＋日本語補足」の形は、上の語彙一覧と整合する。
- ただし**「英語で書くと認識精度が飛躍的に上がる」という主張は、Seedance 2.5 について検証された記述が見つかっていない**（**【未確認】**）。英語表記は語彙を一致させる手段であり、日本語部分を英語へ置き換える必要はない。

### トランジションを指定する

区間の切り替えに特定の見せ方が必要なときは、区間の間に名前で書く。**確度【第三者】**。

`match cut` / `whip pan` / `hard cut` / `continuous camera move`

## 8. プロンプトの骨格

公式の骨格は [SKILL.md](../SKILL.md) の「プロンプトの組み立て」に従う（**素材の役割 → 映像の要約 → 時間順の展開 → 全体の補足**）。第三者の解説では、これと同型の骨格が次のように説明される。**確度【第三者】**。

- 単一ショットの基本形：`〈主体〉が〈場所・環境〉で〈主要な動作〉をする。映像は〈スタイル〉。〈ショットサイズ・アングル・カメラの動き〉を使う。音声は〈セリフ・環境音・効果音・音楽〉。`
- 必須は**主体と動作**の2つで、残りは必要に応じて足す。
- 複雑・長尺の形：`参照素材の宣言 ＋ 一文の要約 ＋ 時間順の展開 ＋ 全体の締め`
- 主体と主要動作は**冒頭に置く**。全体の維持条件・除外条件は**末尾にまとめる**。末尾に一貫したスタイルの1行を置くと、時間指定への追従が良くなるとされる。

### 避けること

- `cinematic` の一語で済ませる。カメラの動きではなく、何も具体的に伝わらない。
- 「カメラを動かす」のような物理的な手がかりのない指示。
- 矛盾するカメラ指示の重ね合わせ（`handheld` と `locked steady` を同時に、右へパンした直後に左へホイップパンして急降下、など）。
- 1区間に無関係な動作を3つ以上積む。
- 曖昧な形容詞に頼る。完成したプロンプトは「短いショット指示書」として読めるべきで、写真のキャプションではない。
